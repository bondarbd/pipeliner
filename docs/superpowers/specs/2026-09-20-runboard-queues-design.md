# runboard: очереди долгов, доска и правило outbound (фаза 1)

Статус: утверждён к реализации 2026-09-20. Продолжение `2026-09-18-runboard-design.md`.

## 1. Зачем

Помимо конечных задач (релиз, МПР) у разработчика есть открытые долги без конца: ответить
человеку в СберЧате, переслать известное, выполнить своё обещание. Их надо захватывать за
одно действие в момент прерывания и разбирать пачкой раз в день, не теряя ссылку на исходный
тред. Первая фаза делает ровно это и ничего больше.

Решения, принятые по итогам брейншторма и UX-оценки:

- Очередь это **хранилище рядом с движком**, а не новый режим движка. Разбор очереди это
  обычный конечный запуск обычного шаблона, который заканчивается за полчаса. Никакого
  демона, планировщика и коннекторов к чату/почте: отправляет человек, панель фиксирует факт.
- Захват стоит **одну строку и одно нажатие**: свободный текст плюс необязательная ссылка.
  Никаких полей «кто/что/срок» при захвате.
- В первой фазе **нет agent-шагов**: очередь работает без настроенного gigacode. Извлечение
  «кто/что/срок» слабой моделью и черновики ответов отложены во вторую фазу.
- Из гардов реализуется одно правило: шаг с `outbound: true` выполняется только сразу после
  human-шага с утвердительным ответом.
- «Позже» это три фиксированные кнопки, не календарь. После трёх откладываний элемент
  закрывается сам с пометкой, чтобы список не зарастал.

## 2. Хранилище очередей

`~/.runboard/inbox/<queue>/<id>.json`, имя очереди `^[a-z][a-z0-9-]*$`, `id` в формате
идентификаторов запусков (`YYYYMMDD-HHMMSS-xxxx`). Файл:

```json
{ "id": "20260920-114012-k3f9", "text": "Петя: где дистрибутив 0.247?", "link": "sberchat://…",
  "createdAt": "…", "status": "open", "until": null, "snoozes": 0, "closedAt": null, "note": null }
```

`status`: `open` | `snoozed` (с `until`, дата `YYYY-MM-DD`) | `done` | `dropped`.
Элемент **открыт**, если `status = open` или `status = snoozed` и `until <= сегодня`.

Операции (`src/queue.js`): `add(home, queue, { text, link })`, `list(home, queue?)` (все
элементы, кроме закрытых старше 30 дней), `open(home, queue)`, `done`, `drop`,
`snooze(home, queue, id, when)`. `when`: `tomorrow`/`завтра`, `monday`/`понедельник`,
`week`/`неделя` или `YYYY-MM-DD`. Третий snooze подряд переводит элемент в `dropped` с
`note: "auto-closed after 3 snoozes"`. Запись файла атомарная (tmp + rename), как `run.json`.

Закрытые элементы не удаляются автоматически в фазе 1; `runboard clean` их не трогает.

## 3. Элементы запуска из очереди

Новый источник элементов шаблона: `items: { source: queue, queue: debts }`. При создании
запуска `Manager.resolveItems` берёт открытые элементы очереди и превращает каждый в элемент
`{ name: id, text, link, createdAt, snoozes }`. Переданный список `--items` для такого
источника игнорируется. Запуск без открытых элементов создаётся и сразу завершается `done`;
CLI печатает `no open items in queue debts`.

Валидатор: `items.source` допускает `queue`, для него обязательно `items.queue`.

## 4. Шаблон `debts`

```yaml
name: debts
title: Долги по ответам
description: Разобрать захваченные долги: ответить руками, отложить или закрыть.
items: { source: queue, queue: debts }
steps:
  - name: reply
    each: true
    human:
      question: "${{ item.text }}"
      options: [Отправил, Завтра, Понедельник, Через неделю, Не нужно]
      pause_on: []
  - name: close
    each: true
    js: ./steps/queue-answer.js
```

`queue-answer.js` читает `ctx.item.steps.reply.answer` и вызывает `ctx.queue.done/snooze/drop`
(новое поле контекста js-шага, см. §6). `Отправил` → `done`, `Завтра`/`Понедельник`/`Через
неделю` → `snooze`, `Не нужно` → `drop`. Возвращает `{ status, until }`.

`human.pause_on: []` — новая возможность: пустой список означает «ни один ответ не ставит
дорожку на паузу» (сейчас по умолчанию «Нет/No»).

Утренний прогон запускает cron ОС:

```
45 8 * * 1-5  cd /path/to/runboard && RUNBOARD_HOME=$HOME/.runboard node bin/runboard.js run debts --yes >> $HOME/.runboard/cron.log 2>&1
```

Без TTY команда останавливается на первом human-шаге (код 2), запуск остаётся
`waiting_for_human`; человек разбирает его утром на доске или в UI запуска. Если `serve`
поднят, cron-команда идёт через его API и ничего не ждёт.

## 5. Захват и CLI

```
runboard add <queue> <text…> [--link URL]      захватить долг; text из stdin, если аргумент "-"
runboard queue [name]                          открытые и отложенные элементы (все очереди без аргумента)
runboard done <queue> <id>
runboard snooze <queue> <id> <tomorrow|monday|week|YYYY-MM-DD>
runboard drop <queue> <id>
runboard board [--all]                         доска: что требует меня сейчас (см. §7)
```

`add` печатает `added <queue>/<id>`. Имя очереди создаётся на лету. Через сервер эти
команды не проксируются: они пишут файлы, движок их не читает до следующего запуска.

## 6. Изменения движка и раннеров

1. **`outbound: true`** на шаге `shell`/`js`/`agent`. Валидатор: непосредственно предыдущий
   шаг того же вида (`each`/`once`) обязан быть `human`. Движок перед запуском клетки с
   `outbound` проверяет ответ предыдущей human-клетки того же элемента: если он не из
   `[Да, да, Yes, yes, Отправить, Подтверждаю]`, клетка получает `skipped` с ошибкой
   `outbound: not confirmed (<ответ>)`. Пометка `outbound` показывается в списке команд при
   доверии шаблону и в UI.
2. **`run_timeout` не тикает, пока ничего не выполняется**: `checkBudgets` проверяет таймаут
   только при `active.size > 0`. Иначе утренний запуск, простоявший день в
   `waiting_for_human`, уходил бы в паузу по бюджету.
3. **`ctx.queue`** в js-раннере: `{ done(queue, id), snooze(queue, id, when), drop(queue, id) }`
   поверх `src/queue.js`, с `home` из конфига.
4. **`human.pause_on: []`** разрешён и означает «без паузы».
5. У элемента появляется `addedAt` (при `createRun` и в `produceItems`) для возраста на доске.

## 7. Доска

Верхний экран UI (`#/`, пункт «Доска» первым в навигации) и команда `runboard board`.
Источники: `manager.list()` плюс живые движки (клетки в `paused`/`waiting`/`interrupted`/
`unverified`, пилот в `waiting`) и `queue.list()`.

Строка доски: `kind` (`run` | `queue`), `group` (имя шаблона или очереди), `item`, `state`
(статус клетки или элемента очереди), `info` (вопрос, ошибка, `until`), `age` (от `addedAt`
или `createdAt`), `link`, `runId`. Сортировка: сначала то, что требует человека, внутри
группы по возрасту. Фильтр по умолчанию «требует меня сейчас»: клетки, ждущие человека, и
просроченные `snoozed`; `--all` / переключатель в UI показывает и открытые элементы очередей,
и идущие запуски.

Сверху доски в UI поле захвата: очередь (по умолчанию `debts`), текст, ссылка, кнопка
«Записать». В таблице у элемента с `link` кнопка «Открыть». Строка запуска ведёт на страницу
запуска, где human-шаги отвечаются как сейчас.

API: `GET /api/board?all=1`, `GET /api/queues`, `POST /api/queues/:name {text, link}`,
`POST /api/queues/:name/:id/done|drop`, `POST /api/queues/:name/:id/snooze {when}`.

## 8. Тесты

- `queue.test.js`: add/list/open/done/snooze (все формы `when`)/drop, авто-закрытие после
  трёх snooze, атомарность записи, фильтр открытых по дате.
- `template.test.js`: `source: queue` требует `queue`; `outbound` без предшествующего human
  это ошибка; `pause_on: []` валиден.
- `engine`: outbound-клетка пропускается при отрицательном ответе и выполняется при
  положительном; `run_timeout` не срабатывает без активных клеток.
- `manager.test.js`: `source: queue` даёт элементы из открытых записей и игнорирует `--items`.
- `cli.test.js`: `add` → `queue` → `run debts --yes --answer Отправил` доводит элемент до
  `done`; `snooze` три раза закрывает элемент; `board` показывает ждущие клетки.
- `api.test.js`: `POST /api/queues/debts`, `GET /api/board`.

## 9. Не в фазе 1

Agent-шаги в `debts` (извлечение «кто/что/срок», черновики), слой фактов, остальные семь
гардов, хеш-дедупликация захвата, очереди `approvals`/`status-digest`/`promises`, фидеры из
СберЧата/почты, автозакрытие по `verify`, встроенный планировщик.
